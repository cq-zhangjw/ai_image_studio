# 16 - 任务进度落库与前端轮询恢复

> 状态：已实施（2026-10-23 完成）· 动因：刷新浏览器后任务进度应恢复显示；进度写入任务表 + 前端轮询

## 1. 方案（采纳用户提议并澄清）

- **核心**：后台推理时把进度（step/total/percent/phase）节流写入 db_tasks；前端进入页面即轮询 `GET /api/tasks` 更新进度，刷新后自动恢复。
- **澄清点**：前端刷新不重启后端，任务仍在内存执行——恢复轮询读内存即可；db 持久化的额外价值是**后端重启后进度/状态有据可查**（不丢信息）。
- SSE 保留为实时通道，轮询做兜底恢复（双通道同源，幂等更新）。

## 2. 后端（backend/app/task_manager.py）

- `_persist_task` 新增 `progress` 字段落库（TaskProgress 序列化）
- `_restore_history` 恢复 progress（dict → TaskProgress）
- 新增 `_progress_flusher` 线程：每 2s 对 running/queued 任务调 `_persist_task`（moofile 写锁串行，与终态写入无冲突；终态必覆盖）

## 3. 前端

- `stores/task.ts`：新增 `startPolling(interval=3000)` / `stopPolling()`——轮询调 `loadHistory(40)` 合并进度
- `App.vue`：onMounted 启动轮询、onUnmounted 停止（全局生效，刷新后任何页面都恢复）

## 4. 验证（实测）

- ✅ 任务进度实时可查：loading model → sampling 75% → 100% → succeeded（GET /api/tasks 每 2-3s 可见变化）
- ✅ 后端重启后历史任务进度完整恢复（task_cf4: step 8/8, 100%, sampling）
- ✅ 前端刷新：提交任务 → running → F5 → 轮询恢复，排队提示/任务状态重新显示，服务端继续执行
- ✅ 旧任务（无 progress 字段）兼容默认值

## 5. 边界

- 后端重启仍会打断执行（内存队列丢失，queued/running 标记 interrupted，进度保留展示）
- 轮询 3s 一次仅本地应用，开销可忽略

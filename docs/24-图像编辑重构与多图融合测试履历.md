# 图像编辑页重构 + 多图融合测试履历

日期：2026-10-24
状态：已完成并实测

## 一、本次改动

### 前端 `frontend/src/views/EditImageView.vue`（整体重写）
1. **功能选择**：顶部 segmented「单图编辑 | 多图融合」，默认单图编辑。
2. **模型过滤**：ModelSelector 新增 `options` prop，编辑页只显示支持编辑的模型：`Qwen-Image-2.1` / `FLUX.2 [klein] 4B`（与后端白名单一致）。
3. **区域设定删除**：标注方式 / 标注图 / Mask / 羽化半径 / 合成保真 全部移除。
4. **采样参数**：折叠面板「采样参数 ▾」，采样步数与种子**分两行**显示（步数 10–40，种子 0=随机）。
5. **多图融合**：素材区 **3×3 九宫格**（9 个上传槽位，最多 9 张，可移除 ×）。
6. **结果与历史布局**（参照文生图/图像放大，3fr:1fr 左右两列）：
   - 左：单图编辑 = 原图/结果滑块对比；多图融合 = 左半素材网格（3 列缩略图）+ 右半融合结果。
   - 右：编辑历史（HistoryGallery type="edit"）。

### 前端 `frontend/src/components/ModelSelector.vue`
- 新增 `options?: {value;name}[]` 过滤 prop，缺省显示全部 7 个模型。

### 后端
- `backend/app/routers/tasks.py`：`POST /api/tasks/edit` 新增 `images: List[UploadFile]` 多文件参数（融合模式，落盘 `_uploads/<task_id>/img0..imgN`）；单图模式（image / src_stamp+src_image）保持兼容；未传任何图 400。
- `backend/app/services/qwen_service.py`：`edit_image` 检测 `_image_paths` 长度 >1 → `util.edit_image(image=[...paths])`（SDK 原生多图列表输入）；单图精确编辑（precise_edit）与全图编辑路径不变。
- 前端不再提交 mark/mask/annotation_style/composite/feather，后端字段保留可选（兼容旧客户端）。

## 二、测试用例与结果

环境：Windows / venv / qwen-image-2.1 / num_inference_steps=20，服务 8001 后台运行。

### 用例 1：单图编辑
- 输入：`outputs/20261024_144405/output_01.png`（沙漠灯塔·飞鸟·少女，1536×864）
- 指令：将天空改为繁星点点的深蓝星空，添加一轮银白色月亮，保持画面其他部分不变
- 任务：`task_59ac7afbd86f4371`
- 结果：**succeeded**，耗时 82.3s（模型加载 24.4s），输出 `outputs/20261024_164756/output_01.png`
- 验证：画面天空变为星空+满月，灯塔/巨鸟/少女主体保留 → 编辑生效

### 用例 2：多图融合（2 张）
- 输入：`outputs/20261024_144405/output_01.png` + `outputs/20261024_144338/output_01.png`（灯塔少女 / 巨鹰长袍）
- 指令：融合为一张：左半灯塔与飞鸟少女，右半巨鹰与长袍人物，中间自然过渡，天空统一深蓝星空
- 任务：`task_063711c039c44390`
- 结果：**succeeded**，耗时 472.5s（模型加载 24.4s），输出 `outputs/20261024_165549/output_01.png`
- 验证：左半灯塔+幽蓝巨鸟+少女、右半巨鹰+长袍人物，星空过渡 → 融合生效

### 用例 3：FLUX.2 [klein] 4B 单图编辑
- 输入：`outputs/20261024_144405/output_01.png`（沙漠灯塔·飞鸟·少女，1536×864）
- 指令：把灯塔改为水晶玻璃灯塔，透出淡蓝光芒，天空变为黄昏橘色渐变，其他元素保持
- 任务：`task_b2494b56d1d9461c`，model=flux2-klein-4b，num_inference_steps=4
- 结果：**succeeded**，耗时 32.1s（模型加载 11.5s），输出 `outputs/20261024_170432/output_01.png`
- 验证：灯塔变为蓝色玻璃钢结构+发光、天空黄昏橘色、少女/羽翼元素保留 → 编辑生效
- 补充：flux2-klein-4B 权重已在 `models/FLUX.2-klein-4B`（7.75GB safetensors），加载约 11.5s；**该模型仅支持单图编辑**（后端分发路径只取 `_image_path`），融合模式选 flux2 会失败，前端需在融合模式下禁用 flux2（见遗留）。

### 用例 4：FLUX.2 [klein] 4B 多图参考融合
- 输入：`outputs/20261024_144405/output_01.png` + `outputs/20261024_144338/output_01.png`（灯塔少女 / 巨鹰长袍）
- 指令：参考两张图融合为一张，左侧灯塔神鸟、右侧巨鹰人物，黄昏沙漠奇幻风
- 任务：`task_ff8a1d8b55134487`，model=flux2-klein-4b，steps=4
- 结果：**succeeded**，耗时 27.7s（模型加载 7.6s），输出 `outputs/20261024_172856/output_01.png`
- 验证：左侧灯塔+幽蓝鹰形生物（A），右侧巨鹰+长袍人物+少女（B+A），黄昏风格统一 → 多参考融合生效
- 后端改动：`flux2_service.edit_image` 支持 `_image_paths` 列表（SDK `edit_image` 本就支持多参考图），`tasks.py` flux2 分发兼容无 `_image_path` 的多图任务；**融合模式选 FLUX.2 已可用**

### 结论
- 单图编辑链路（新前端表单字段 → 后端 → qwen 全图编辑）正常。
- 多图融合链路（images 多文件 → 落盘多图 → SDK 列表输入）正常，**6 张上限由前端网格约束（3×2，2026-10-25 由 9 格改 6 格）、后端无数量硬限**。
- **Qwen 与 FLUX.2 均支持多图融合**：qwen 走编辑式融合（472s，上下文长、质量稳）；flux2 走提示词参考融合（28s，速度快）。
- 融合模式推理耗时显著高于单图（qwen 472s vs 82s），与多图输入上下文长度相关。

## 三、GGUF 引擎切换（2026-10-25 追加）

- Qwen-Image-2.1 全部能力（文生图/单图编辑/多图融合/扩图）已切换为 **stable-diffusion.cpp GGUF 子进程引擎**（`qwen_service.py` → `utils.qwen_21_gguf_util.py`，同名同签名无缝替换，调用方零改动），详见 **docs/26**。
- 性能对比：Qwen 多图融合 1024²@20 步 **104.2s**（原 diffusers 1665s，快 16 倍）；单图编辑 864×1088@12 步 79.9s（采样 5.2s/步）。
- 实测确认：单图/多图均启动 `sd-cli.exe` 子进程（nvidia-smi 可见，显存 10.9G→19G）。

# 06 - 提示词优化功能设计（离线 LLM + GPU 推理）

> 状态：已批准实施 · 日期：2026-10-22 · 更新：2026-10-25（LLM 引擎 GGUF 化，见 docs/27）· 关联：docs/01~05（Web UI 多模型生成平台）

## 1. 目标

在文生图/图像编辑页提供"提示词优化"能力：调用**本地离线 LLM**，将用户输入的简短描述扩写为可直接用于扩散模型的详细提示词，通过 UI 弹窗预览并一键回填。

## 2. 模型选型

| 项 | 结论 |
|---|---|
| 模型 | **Qwen3.8-9B-Q6_K.gguf**（llama.cpp GGUF 量化，`models/gguf/`） |
| 推理引擎 | **llama-cli.exe 子进程**（llama.cpp CUDA 版，一次性推理，零驻留显存） |
| 封装 | `utils/guff_util.py`（run_llama_cpp：-ngl 99 -c 4096 -st --reasoning off） |
| 显存 | 子进程运行期间短暂占用（~7GB），退出即释放；**无驻留** |
| 指令跟随 | 中文指令跟随正常（单段指令实测零复述，见 docs/27 §4） |
| 依赖 | **零 Python 新依赖**（llama-cli 独立可执行文件） |

> 2026-10-25 变更：原 Qwen3.5-4B-Instruct（transformers GPU 驻留）已替换为 GGUF 子进程方案，显存策略从"共存/卸载矩阵"简化为"零驻留天然共存"。

## 3. 显存策略（3080 20G）

**llama.cpp 子进程模式：每次推理为独立 llama-cli 子进程，运行期间短暂占用显存，退出即释放，不驻留。**

- `llm_service.should_unload_for(model)` **恒为 False**：图像任务执行前无需卸载 LLM。
- `llm_service.ensure_ready()` 空操作（构造即就绪）。
- `unload()` 仅重置单例句柄，无 torch 操作。
- 原 transformers 驻留时代的分级共存矩阵（LLM 8GB 与图像模型排队卸载）**已废弃**。

## 4. 架构与接口

```
前端 TextToImageView.vue / EditImageView.vue
   │  POST /api/prompt/optimize {prompt, target_model}
   ▼
backend/app/routers/prompt.py          # 轻量同步推理放线程池
   ▼
backend/app/services/llm_service.py   # 懒加载单例 + 子进程语义（should_unload_for=False）
   ▼
utils/llm_prompt_optimizer.py         # PromptOptimizer（模板、_complete 拼接、超时）
   ▼
utils/guff_util.py                    # run_llama_cpp（子进程调用 llama-cli.exe）
   ▼
llama-cpp/llama-cpp-cu124/llama-cli.exe + models/gguf/Qwen3.8-9B-Q6_K.gguf
```

**接口定义**：`POST /api/prompt/optimize`
```json
请求：{ "prompt": "夏日冰饮节海报", "target_model": "auto" }
响应 200：{
  "original": "夏日冰饮节海报",
  "optimized": "夏日冰饮节海报：画面中央是一杯晶莹剔透的薄荷绿苏打...",
  "elapsed_seconds": 5.5,
  "model": "Qwen3.8-9B-GGUF (llama.cpp)"
}
错误 4xx/5xx：{ "detail": { "code": "...", "message": "..." } }
```

- `target_model`: `auto | qwen-image-2.1 | flux2-klein-4b | z-image-turbo | sana-sprint-1.6b`，决定模板语言偏好（FLUX/SANA 输出英文详细描述；Qwen/Z-Image 中英混合；auto 默认中文描述+英文关键词）。
- 独立于 TaskManager 图像队列；同步推理经 `run_in_executor` 不阻塞事件循环。
- 超时保护：`max_new_tokens=256`、`temperature=0.7`，单次调用硬超时 30s。

## 5. Prompt 模板（System）

```
你是专业的 AI 图像生成提示词优化器。请将用户描述直接扩写为可用于扩散模型的详细提示词并输出结果：
严格保留用户核心意图与主体，补充主体外观动作、场景环境、光线氛围、构图布局、艺术风格、
色彩基调、镜头语言、质感纹理等细节，输出 120-220 词的一段连贯文字，不加任何前缀。目标模型偏好：{pref}
```

> 2026-10-25 更新：原"编号规则列表"模板（规则 1)2)3)4)）导致模型先复述规则再输出；已单段化为自然语言指令，实测零复述（见 docs/27 §4）。

偏好描述映射：
- qwen-image-2.1 / z-image-turbo：中英混合，海报场景强调版式与可读文字
- flux2-klein-4b：英文为主，强调细节描述（无 prompt upsampling）
- sana-sprint-1.6b：英文为主，简洁明确
- auto：中文主体描述 + 英文风格关键词

## 6. UI 设计

- **入口**：提示词文本框右上角悬浮 ✨ 按钮（容器 relative，按钮 absolute 右上角）。
- **流程**：
  1. 点击 ✨ → 按钮 loading（"优化中…"），调 `/api/prompt/optimize`（携带当前输入框内容与所选模型）。
  2. 弹窗 Modal：左"原文"只读、右"优化结果"可编辑 textarea；顶部显示耗时/模型；底部「应用」「复制」「关闭」。
  3. 「应用」→ 优化结果回填输入框并关闭弹窗，**不自动提交**。
  4. 空输入时按钮禁用。
- **组件**：`frontend/src/components/PromptOptimizerModal.vue`（按钮+弹窗一体），`props: modelValue`（原文）、`modelId`（当前生成模型），`emit: apply(text)`。
- **接入**：TextToImageView.vue、EditImageView.vue 主提示词区。

## 7. 实施步骤

1. 下载模型：`Qwen3.8-9B-Q6_K.gguf`（7.04GB）至 `models/gguf/`；llama.cpp CUDA 版解压至 `llama-cpp/llama-cpp-cu124/`（详见 docs/27 §6）。
2. `utils/guff_util.py`：llama-cli 子进程封装（run_llama_cpp）。
3. `utils/llm_prompt_optimizer.py`：PromptOptimizer（模板、_complete 拼接、gpu_memory_info），内部调 guff_util。
4. 后端：`schemas.py` 请求体、`services/llm_service.py`（子进程语义：should_unload_for=False、ensure_ready 空操作、unload 去 torch）、`routers/prompt.py`、`main.py` 注册路由。
5. 任务分发（tasks.py）：`should_unload_for` 恒 False，图像任务不再卸载 LLM。
6. 前端：`PromptOptimizerModal.vue` + 两页接入 + `npm run build`。
7. 重启服务（0.0.0.0:8001），API 实测（中文短句/英文短句/空输入/与图像任务并行），UI 验证。
8. 交付：图片/文档/截图 + 在线可访问。

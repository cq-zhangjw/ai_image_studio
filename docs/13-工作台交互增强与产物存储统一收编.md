## 2. 产物存储统一收编（7b）

### 布局

```
db/db_works_<hash8>/            # 作品库（moofile）
  db.bson                       # works 表：{stamp, type, model, prompt, params, images[], images_pinned{}, pinned, created_at}
  meta.json
  images/<stamp>/<output_01.png>   # 正式产物图片文件
```

- 新生成任务成功 → `task_manager._ingest_works` 把图片复制进 `db/images/<stamp>/` 并登记 works 记录（`works_store.ingest_batch`，幂等）
- 启动时 `works_store.migrate_legacy` 把 outputs/ 历史批次收编进 works（图片复制 + prompt/params 重新解析）
- outputs/ 仅作为内部测试来源与文件服务回退（`works_store.resolve_image`：db/images 优先 → outputs 回退）

### API 变化

- `GET /api/outputs`：主数据源改为 works 库（pinned 状态存 `images_pinned`），遗留 outputs 批次兜底
- `GET /api/outputs/{stamp}/{image}`：替换 StaticFiles，自定义文件服务（db 优先）
- `POST /api/gallery/pin|unpin`、`DELETE /api/gallery/{stamp}/{image}`：优先操作 works 表，未收编批次回退 gallery_store
- `_to_web_paths`：按 `stamp+filename` 生成 URL，不依赖 outputs 相对路径

### 兼容性

- 历史 83 个 outputs 批次已全部收编（图片复制 db/images）
- 任务记录（db_tasks）不变；主页卡片参数标签来源：task.params → works.params
- 删除操作同时清理 db/images + outputs 两处文件与 works/gallery 记录
